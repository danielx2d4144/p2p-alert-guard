How it works

Three steps before you release

No screenshots, no trust in the buyer. The answer comes from Paystack's own records.

1

Enter the buyer's claim

The payment reference and the amount the buyer says they sent. Your bot can send the same thing to the API.

2

We ask Paystack, over zkTLS

Alert Guard looks the transaction up on Paystack through Reclaim zkTLS. Your secret key stays inside the TLS session; customer details are redacted from the proof.

3

Get a clear verdict and receipt

Safe to release only if the payment succeeded, the amount is exact, it's in Naira and the reference was never used before. The decision proof goes to zkVerify.

    For developers and bots

    One call before every release

    Wire it into your P2P bot or escrow flow. The response is a machine-readable verdict your release step can enforce.

    Request
    curl -X POST https://p2p-alert-guard.vercel.app/check \
  -H 'content-type: application/json' \
  -d '{"reference":"p2pguard-ok-002","expected_amount_ngn":500000,"trade_id":"order-1234"}'
    Response (trimmed)
    {
  "check_id": "chk_…",
  "decision": "REJECT",          // or "APPROVE_RELEASE"
  "reason_code": "AMOUNT_MISMATCH", // "OK" when approved
  "detail": "paid ₦50,000 but claim says ₦500,000",
  "attested": { "status", "amount_ngn", "currency", "txid", "mode" },
  "zktls": { "identifier", "attestor", "cached", "proof_url" },
  "zkverify": { "circuit", "public_signals", "submission": { "status", "jobId" } }
}
    • POST/check

      Body: reference, expected_amount_ngn, optional trade_id, payee. Add ?full=1 for proofs inline.

    • GET/api/result?id=chk_…

      The stored check, including the full Reclaim and Groth16 proofs.

    • GET/api/zkverify?id=chk_…

      zkVerify job status: Submitted → IncludedInBlock → Finalized, with the tx hash and explorer link.

    • GET/health

      Configuration, store status and zkTLS proof usage.

    Reason codes: OK, NOT_FOUND, NOT_SUCCESS, AMOUNT_MISMATCH, CURRENCY_MISMATCH, REFERENCE_REUSED, PAYEE_MISMATCH, TEST_MODE_PAYMENT, plus fail-closed errors. Anything unproven is a REJECT.
